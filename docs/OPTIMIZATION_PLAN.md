# План оптимизации размера сборки WebGL

**Цель:** 52 МБ → **~8–12 МБ**, без заметной потери качества. Первая загрузка на телефоне по 4G — с 15–30 с до ~3–6 с, меньше расход памяти (стабильность на слабых телефонах и Safari).

Документация по проекту — [DOCUMENTATION.md](DOCUMENTATION.md).

---

## 0. Исходные цифры (сборка от 2026-09-18)

Из `Logs/webgl_build.log`, раздел `Build Report`, и размеров файлов в `Builds/WebGL/Build`:

| Что | Размер |
|---|---|
| Вся сборка (сжатая, скачивается браузером) | **52.0 МБ** |
| ├ `WebGL.data.unityweb` — ресурсы (картинки, звук, шрифт) | 44.9 МБ |
| ├ `WebGL.wasm.unityweb` — код движка и игры | 9.5 МБ |
| └ `framework.js` + `loader.js` | 0.1 МБ |
| Ресурсы в распакованном виде | 183.3 МБ, из них **текстуры 178.9 МБ (97.6%)** |

**Главные находки:**

1. **Текстуры вообще не сжаты** (RGBA32, 4 байта на пиксель + mip-карты). Кадр кота 640×512 = **1.7 МБ**. Любой GPU-формат (DXT/ASTC) даёт в 4–8 раз меньше.
2. **У кадров котов ~62% холста — пустота.** Кот занимает 35–41% кадра 640×512 (замер по всем 88 кадрам: 30.4 Мпикс холста, 11.7 Мпикс содержимого).
3. **Мелкий интерфейс хранится в огромном разрешении.** Лапки-иконки: 2.9 МБ каждая, а на экране 54 px. Рамка портрета и её маска: по 4.9 МБ, на экране 214 px.
4. **Встроенная заставка «Made with Unity»:** 2.7 МБ и ~2 с задержки при старте.
5. **Код:** 9.5 МБ — в сборку попадают неиспользуемые пакеты (Visual Scripting, AI Navigation, Timeline), а в логе линковки видно `debug_WebGL_wasm` — код оптимизирован «на быструю сборку», а не на размер.

Крупнейшие файлы (распакованный размер):

```
6.0 МБ  UI/Arena/arena_background.jpg     (1672×941 — высота не кратна 4, не сжимается в DXT)
4.9 МБ  UI/portrait_frame.png, UI/portrait_mask.png  (1024×937, на экране 214 px)
3.3 МБ  UI/timer_splash.png               (на экране 300 px)
2.9 МБ  UI/paw_filled.png, UI/paw_empty.png  (на экране 54–66 px)
```

## Порядок работы

Каждый шаг — **отдельный коммит**, после каждого — сборка и проверка (см. раздел «Проверка»). Если шаг что-то сломал — `git revert` этого коммита.
Перед сборкой в фоне Unity должна быть **закрыта**.

| # | Шаг | Качество | Ожидаемая экономия |
|---|---|---|---|
| 1 | Уменьшить мелкий интерфейс до размера на экране | без потерь (на экране то же) | ~15 МБ распакованного → ~4 МБ в сборке |
| 2 | Сжатие текстур для WebGL (DXT для ПК + ASTC для телефонов) | почти без потерь | ×4–8 по текстурам |
| 3 | Атласы спрайтов (плотная упаковка, без пустых полей) | без потерь | ~−60% пикселей котов |
| 4 | Убрать заставку «Made with Unity» | без потерь | 2.7 МБ и 2 с при старте |
| 5 | Код: убрать лишние пакеты, стриппинг, оптимизация wasm на размер | без потерь | wasm 9.5 → ~5–6 МБ |
| 6 | Музыка: сжатие / укорачивание | чуть-чуть (незаметно) | 2.6 → ~1.2 МБ |
| 7 | Brotli вместо Gzip | без потерь | ещё −15–20% |
| 8 | *(только с одобрения)* Crunch-сжатие атласов | малые потери, настраиваемые | ещё ×2–3 по текстурам |

## Шаг 1. Мелкий интерфейс — до реального размера на экране

**Идея:** хранить картинку не больше, чем ~1.5–2× её размера на экране при 1080p. Больше не видно никогда, даже с mip-картами.

Размеры (на экране при 1920×1080 → целевой размер файла):

| Файл | На экране | Сделать |
|---|---|---|
| `paw_empty.png`, `paw_filled.png` | 54–66 px | **128** px по длинной стороне |
| `Portraits/*_portrait_*.png` | ~150 px | **256** |
| `portrait_frame.png` + `portrait_mask.png` | 214–460 px (экран выбора) | **512** (строго одинаково — маска должна совпадать с рамкой) |
| `timer_splash.png` | 300 px | **512** |
| `name_murzik.png`, `name_belchik.png`, `End/wins_*.png` | 330–760 px | **768** |
| `healthbar_frame.png` + `healthbar_fill.png` | 740 px | 1024 (оставить, строго одинаково) |
| логотипы, баннеры раундов, `End/title_*`, `End/button_retry` | ~1000 px | 1024 (оставить) |
| `Arena/arena_background.jpg` | весь экран | оставить 1672 по ширине, но **высоту сделать кратной 4**: 1672×940 (иначе не сожмётся в DXT) |

**Как:** Python-скриптом (Pillow, LANCZOS) пересохранить файлы в `Assets/Art/UI` — **оригиналы уже есть в `SourceArt/UI`**. Удобно добавить в `Tools/` скрипт `prepare_ui.py`, который берёт исходники из `SourceArt/UI`, обрезает, уменьшает до таблицы выше и кладёт в `Assets/Art/UI` — тогда шаг повторяем при любой новой картинке.

Всё, что остаётся отдельными текстурами (не в атласе), должно иметь **обе стороны кратными 4** — иначе GPU-сжатие не применится. Скрипт должен дополнять холст прозрачными пикселями до кратности 4.

## Шаг 2. Сжатие текстур для WebGL

**Сначала проверить, почему сейчас RGBA32.** Открыть любой кадр (`Assets/Art/Murzik/murzik_idle_01.png`) → Inspector → вкладка платформы **WebGL** → посмотреть Format. Или в коде: `TextureImporter.GetPlatformTextureSettings("WebGL")` и `GetAutomaticFormat("WebGL")`.

**Что сделать:**
1. **Build Profiles / Player Settings → WebGL → Texture Compression Formats**: включить **DXT** (ПК) и **ASTC** (телефоны). Unity соберёт ресурсы в двух вариантах, и загрузчик скачает только нужный браузеру. Проверить, какой API у Unity 6.6: `EditorUserBuildSettings.webGLBuildSubtarget` / настройки Build Profile; если мультиформат недоступен — собрать ASTC (телефоны важнее) и проверить, что ПК-браузер его понимает (иначе Unity распакует на лету — медленнее).
2. В `ArtImportSettings.Apply` — поднять `GetVersion()` до 3 и явно задать сжатие:
   ```csharp
   importer.textureCompression = TextureImporterCompression.Compressed; // "Normal Quality"
   importer.crunchedCompression = false;                                // Crunch — только на шаге 8
   ```
   (при необходимости — override для платформы WebGL через `SetPlatformTextureSettings`).
3. Для кадров, которые попадут в атлас (шаг 3), формат задаётся в настройках **атласа**, а не картинок.

**Риск:** полосы/пятна на плавных градиентах (свечение суперударов, огонь). Сравнить скриншоты до/после на кадрах `*_super_05` и портретах. Если видно — для этих картинок качество «High Quality» или ASTC с меньшим блоком (4×4 / 5×5).

## Шаг 3. Атласы спрайтов

**Идея:** все кадры одного кота укладываются плотно в несколько больших текстур без пустых полей. Пиксели котов не меняются, pivot (точка между лап) и выравнивание по полу сохраняются — Unity хранит их в каждом спрайте.

**Что сделать** (лучше скриптом редактора — меню `Cat Fighter → Создать атласы`, как мы любим):
1. **Project Settings → Editor → Sprite Packer Mode = Sprite Atlas V2 – Enabled** (`EditorSettings.spritePackerMode = SpritePackerMode.SpriteAtlasV2`).
2. Создать атласы (`.spriteatlasv2`, API `SpriteAtlasAsset` + `SpriteAtlasImporter`), папка `Assets/Art/Atlases/`:

   | Атлас | Содержимое | Packing |
   |---|---|---|
   | `Murzik.spriteatlasv2` | папка `Assets/Art/Murzik` | **Tight**, padding 4, rotation выкл. |
   | `Belchik.spriteatlasv2` | папка `Assets/Art/Belchik` | **Tight**, padding 4, rotation выкл. |
   | `UI.spriteatlasv2` | мелкий UI: лапки, рамка/маска портрета, портреты, табличка таймера, таблички имён | **НЕ Tight** (Rect), padding 4 |

   Общие настройки: Max Texture Size 2048 (несколько страниц — нормально), **Generate Mip Maps = вкл** (иначе вернётся рябь), Filter = Trilinear, sRGB вкл, Alpha Is Transparency вкл, формат — как в шаге 2.
3. **Почему UI без Tight:** `Image` в UI рисует прямоугольник спрайта; при плотной упаковке в него попадут куски соседних спрайтов. У `SpriteRenderer` (коты) такой проблемы нет — он использует сетку спрайта (у нас Mesh Type = Tight).
4. Большие UI-картинки (фон, логотипы, баннеры, полоски здоровья) **в атлас не класть** — они и так почти без пустоты; им достаточно шагов 1–2.
5. `Mask` на портрете использует альфу спрайта маски — после атласа проверить, что окно рамки обрезает портрет как раньше.

**Ожидаемо:** 88 кадров котов (30.4 Мпикс холста) → ~12 Мпикс содержимого → примерно 3–4 страницы 2048×2048 на обоих котов.

## Шаг 4. Убрать заставку «Made with Unity»

В Unity 6 заставку можно отключить и на бесплатной лицензии (Personal). `PlayerSettings.SplashScreen.show = false` — добавить в `WebGLBuild.Build` рядом с остальными настройками. Проверить в логе, что `Built-in Texture2D: Splash Screen Unity Logo` исчез из Build Report. Если лицензия не позволяет — оставить, но это 2.7 МБ.

## Шаг 5. Код (wasm)

1. **Убрать неиспользуемые пакеты** из `Packages/manifest.json` (сначала `grep` по `Assets/` и сцене, что они правда не используются):
   - `com.unity.visualscripting` — не используем;
   - `com.unity.ai.navigation` — не используем;
   - `com.unity.timeline` — не используем (проверить, что в сцене нет PlayableDirector);
   - `com.unity.collab-proxy` — только редактор (Unity VCS), у нас git — можно убрать.

   `com.unity.test-framework` — только редактор, в сборку не попадает; можно оставить.
   Встроенные модули (`com.unity.modules.*`: physics, terrain, cloth, vehicles, wind, video, xr, umbra, vectorgraphics…) при включённом **Strip Engine Code** (у нас `stripEngineCode: 1`) вырезаются автоматически, если не используются. Убирать их из manifest — по желанию и по одному, с проверкой сборки.
2. **Managed Stripping Level = Medium** (сейчас не задан — по умолчанию). *High* даст ещё меньше, но может сломать Input System (рефлексия) — пробовать только с проверкой управления; при проблемах добавить `Assets/link.xml`, сохраняющий `Unity.InputSystem`.
3. **Оптимизация кода WebGL = «Disk Size with LTO»** (сейчас, судя по `debug_WebGL_wasm` в логе, — «Shorter Build Time»). API Unity 6: `UnityEditor.WebGL.UserBuildSettings.codeOptimization = WasmCodeOptimization.DiskSizeLTO` (свериться с документацией 6.6). Сборка станет дольше, файл — меньше и быстрее.
4. **IL2CPP Code Generation = Optimize Size** (`PlayerSettings.SetIl2CppCodeGeneration(NamedBuildTarget.WebGL, Il2CppCodeGeneration.OptimizeSize)`).
5. Exception Support оставить «Explicitly Thrown Exceptions Only» — пригодится для диагностики.

Все настройки — задавать **в коде `WebGLBuild.Build`**, чтобы они не терялись и были видны в git.

## Шаг 6. Музыка

`music.ogg` (113 с, стерео, ~128 кбит/с) = 2.6 МБ. Варианты (выбрать с пользователем, на слух):
- настройки импорта AudioClip для WebGL: Compression Format Vorbis/AAC, **Quality 50–60%** → ~1.2–1.5 МБ;
- или укоротить луп до лучших 45–60 с (для рекламной версии всё равно нужен короткий кусок).

Короткие звуки уже моно и маленькие — не трогать.

---

## Шаг 7. Brotli вместо Gzip

`PlayerSettings.WebGL.compressionFormat = WebGLCompressionFormat.Brotli` (Decompression Fallback оставить **включённым** — GitHub Pages не отдаёт заголовок `Content-Encoding: br`, распакует загрузчик). Даёт ещё 15–20%. Проверить время запуска на телефоне: распаковка Brotli в JS медленнее, чем Gzip; если старт заметно дольше — вернуть Gzip. На своём сервере можно отдавать `.br` с правильными заголовками — тогда распаковывает браузер, быстро.

---

## Шаг 8 (только после одобрения). Crunch

`Use Crunch Compression` в настройках атласов котов, Compressor Quality 80–100. Сжимает скачиваемый файл ещё в 2–3 раза, но это сжатие с потерями. **Показать пользователю скриншоты до/после** (крупно: шерсть, глаза, огонь супера) — решает он.

## Проверка после каждого шага

1. **Размер:** в конце `Logs/webgl_build.log` — строка `Cat Fighter: WebGL собран (… МБ)` и блок `Build Report` (категории и крупнейшие файлы). Записывать в таблицу ниже.
2. **Игра целиком:** выбор бойца → 2 раунда → нокаут → экран итогов, без ошибок в консоли браузера. При ошибке — отладочная сборка `WebGLBuild.BuildDev` (см. DOCUMENTATION.md).
3. **Картинка:** скриншоты ПК и телефона до/после — коты (шерсть, глаза), суперудары (свечение), портреты в рамках (маска), полоски здоровья, отсутствие ряби при движении.
4. **Телефон:** время первой загрузки по 4G, отсутствие вылетов.
5. **Кнопка «Настроить бойцов»** — работает как раньше (спрайты в атласе остаются теми же ассетами; ссылки не меняются).
